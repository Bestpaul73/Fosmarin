# FOSMARIN: подготовка контактной формы для easyname

Статус на 27 октября 2026: обработчик загружен на easyname и проверен
настоящим SMTP-письмом через `/api/contact.php`. API вернул `ok: true`,
письмо получено в ящике `info@fosmarin.eu`. Доставка во входящие подтверждена.
Заглушка остаётся на месте; полный сайт продолжает работать на Vercel.

## Что именно переносим

React отвечает за поля формы, проверку перед отправкой, курсор ожидания,
блокировку кнопки и сообщения на семи языках. Это остаётся прежним.

Серверный обработчик принимает запрос, повторно проверяет данные и отправляет
письмо. На Vercel это `api/contact.js` с Nodemailer. На easyname будет
`api/contact.php` с PHPMailer. Это две реализации одного интерфейса.

| Действие | Сейчас на Vercel | После переноса на easyname |
| --- | --- | --- |
| Адрес запроса браузера | `/api/contact` | `/api/contact` |
| Формат данных | JSON | JSON |
| Исполнитель серверного кода | Node.js | PHP 8.2 или новее |
| Почтовая библиотека | Nodemailer | PHPMailer |
| Доставка почтовому серверу | SMTP с TLS | SMTP с TLS |
| Секреты | Environment Variables | Конфигурация в `.private`, HTTP-доступ запрещён |

**HTTP и SMTP — разные соединения.** Браузер связывается с сайтом по HTTPS.
Затем сервер сайта отдельно связывается с `smtp.easyname.com:465` по SMTPS.
Пароль SMTP нужен только серверу; браузер его не получает.

## Что такое Composer и vendor

Composer управляет PHP-библиотеками примерно так же, как npm управляет
JavaScript-зависимостями. `composer.json` описывает требования,
`composer.lock` фиксирует версии, а `vendor` содержит скачанный код библиотек.
`vendor/autoload.php` позволяет подключить их без ручного перечисления файлов.

Если полученный архив уже содержит `hosting/easyname/private/vendor`,
PHPMailer в нём уже установлен. Повторять установку сразу не нужно.
Для чистой копии из Git (без vendor) после установки PHP и Composer
зависимости устанавливаются командой из корня проекта:

```powershell
composer install --working-dir=hosting/easyname/private --no-dev --prefer-dist
```

Здесь зафиксирован PHPMailer 7.1.1. Требования проекта рассчитаны на PHP 8.2+.
Конфигурация Composer учитывает PHP 8.2 при выборе зависимостей.
`vendor` не коммитим, но перед загрузкой на хостинг его нужно включить в пакет.
Файлы лицензии PHPMailer сохраняются вместе с библиотекой.

## Почему PHP снова проверяет поля

Проверка React помогает человеку заполнить форму. Но запрос можно отправить
напрямую, поэтому сервер не доверяет результату проверки в браузере.

Обязательные поля: имя, email, тема, сообщение. Организация необязательна.
Лимиты сохранены: имя 120, email 254, организация 200, тема 200,
сообщение 5000 единиц длины JavaScript.

Обычный `strlen()` PHP считает байты: русские и греческие буквы занимают
больше одного байта. Поэтому в коде есть отдельный подсчёт длины,
совместимый с JavaScript. Emoji вне основной Unicode-плоскости считаются
за две единицы, как в JavaScript `.length`.

Тема и имя не могут содержать переводы строк: так предотвращается подстановка
дополнительных почтовых заголовков. Сообщение при этом может быть многострочным.
Всё письмо отправляется обычным текстом, не HTML.
Тело HTTP-запроса ограничено 64 КиБ; слишком большой запрос не читается целиком.

## Honeypot и адреса

`fax_number` — скрытое поле-ловушка. Если оно заполнено, сервер отвечает успехом,
но письмо не отправляет и SMTP не подключает. Это простая защита от части ботов,
а не гарантия отсутствия спама.

From и To берутся только из закрытой конфигурации:

- From: `noreply@fosmarin.eu`;
- To: `info@fosmarin.eu`;
- адрес посетителя: в теле письма;
- Reply-To: отсутствует по результату расследования easyname.

Кнопка «Ответить» в почтовом клиенте не подставит адрес посетителя.
Его нужно скопировать из текста письма в поле получателя.
Пароль не обрезается функцией trim: пробел может быть частью пароля.

## Ответы сервера

| HTTP | JSON-код | Значение |
| --- | --- | --- |
| 200 | `ok: true` | SMTP принял письмо либо сработал honeypot |
| 400 | `VALIDATION_ERROR` | Неправильные поля или повреждённый JSON |
| 405 | `METHOD_NOT_ALLOWED` | Разрешён только POST |
| 413 | `REQUEST_TOO_LARGE` | Превышен лимит тела запроса |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | Ожидается `application/json` |
| 503 | `MAIL_NOT_CONFIGURED` | Нет закрытой конфигурации или библиотеки |
| 500 | `MAIL_SEND_FAILED` | Ошибка SMTP/отправки |

Код 200 после SMTP означает приём письма сервером, а не гарантию папки
«Входящие». Это проверяется отдельным реальным тестом доставки.
Форма уже умеет показывать существующее сообщение об ошибке при HTTP-ошибках.
Подробности ошибок, пароли и текст письма не выдаются в HTTP-ответе.
Наш журнал записывает только общий код сбоя; SMTP-debug выключен.

## Как файлы будут лежать на сервере

`WEBSPACE` означает корневой каталог аккаунта, видимый в FTP.
Для нашего аккаунта абсолютный путь — `/data/web/e150313`.

| Путь на сервере | Доступ через сайт |
| --- | --- |
| `WEBSPACE/html/fosmarin-project/api/contact.php` | Публичная точка входа |
| `WEBSPACE/html/fosmarin-project/.private/.htaccess` | Запрещает HTTP-доступ к содержимому `.private` |
| `WEBSPACE/html/fosmarin-project/.private/src/contact.php` | Доступ PHP с диска, HTTP запрещён |
| `WEBSPACE/html/fosmarin-project/.private/vendor/` | Доступ PHP с диска, HTTP запрещён |
| `WEBSPACE/html/fosmarin-project/.private/contact-config.php` | SMTP-настройки с паролем; HTTP запрещён |

Поддержка easyname подтвердила, что административный `open_basedir` не позволяет
PHP читать `/files/fosmarin`, а добавить исключение при включённом ограничении
на этом тарифе нельзя. `.user.ini` не может расширить это ограничение.
По рекомендации поддержки используем `.private` внутри разрешённого каталога
сайта. `open_basedir` оставляем включённым.

Точка в имени `.private` сама по себе не защищает файлы. Защиту обеспечивает
`.htaccess` с директивой Apache `Require all denied`. Не удалять этот файл и
не добавлять разрешающие вложенные `.htaccess`. Запрет HTTP не мешает PHP
читать эти файлы напрямую с диска.

В исходниках папка `hosting/easyname/private` сохраняет своё имя; сборщик
помещает её содержимое в `package/html/fosmarin-project/.private`.
Сборщик проверяет наличие запрета доступа перед созданием пакета.
Путь к `.private` вычисляется из расположения `api/contact.php`.

### Сначала проверяем защиту, затем вводим пароль

1. Загрузить `.private/.htaccess` в соответствующую папку сайта первым.
2. Загрузить файлы пакета без настоящего `contact-config.php` и без пароля.
3. Через HTTPS на фактическом домене сайта проверить прямые GET-запросы:
   `/.private/composer.json` и `/.private/contact-config.example.php`.
   Оба существующих файла должны вернуть HTTP **403 Forbidden**.
   Проверить также файл во вложенной папке: `/.private/src/contact.php`.
4. HTTP 200 с пустым телом, редирект на заглушку или HTTP 404 не подтверждают
   работу запрета. При таком результате не вводить пароль; проверить конфигурацию.
5. Только после подтверждения 403 скопировать образец на сервере в
   `.private/contact-config.php` и заполнить SMTP-пароль. Повторно проверить
   HTTP 403 для `/.private/contact-config.php`.

Настоящий `contact-config.php` не должен попадать в Git и в сборочный пакет.
Не загружать содержимое `private` отдельно от защитного `.htaccess`.
28 октября 2026 редирект домена без www исправлен в панели easyname:
Target URL — `https://www.fosmarin-project.eu/`, включено сохранение пути
и параметров, Permanent redirection пока выключен. Проверено: 302 сохраняет
HTTPS, путь и query; затем `/api/contact` возвращает 405. Старый ответ мог
оставаться в кеше; повторная проверка выполнена с новым query-параметром.

## Текущая маршрутизация API и будущие правила полного сайта

React обращается к `/api/contact`, а реальный файл называется `api/contact.php`.
Правило Apache выполняет внутреннее перенаправление к PHP без изменения URL.

`public/.htaccess` — текущие минимальные правила API рядом с заглушкой.
Этот файл автоматически включается в пакет обработчика, поскольку сборщик
копирует `public`. Файл `private/.htaccess` независимо защищает `.private`.
`api-routing.htaccess.example` сохраняется как справочный фрагмент API.

`full-site.htaccess.example` — отдельная конфигурация для будущего полного
React-сайта в корне домена. Не загружать её вместо текущего `.htaccess`
до согласованного запуска: иначе известные страницы будут получать HTML заглушки.
В будущем она применяется как корневой `.htaccess` вместе с настоящей сборкой React.
Защитный `.private/.htaccess` сохраняется.

Генерация из существующих источников навигации и языков:

```powershell
node scripts/generate-easyname-routing.js
```

При добавлении страницы или языка повторить генерацию. Скрипт меняет только
`full-site.htaccess.example`, а не текущий `public/.htaccess`.
Правила отдают файлы обычным способом, известные страницы — через `index.html`
с HTTP 200, неизвестные адреса — через `ErrorDocument 404 /index.html`
с настоящим статусом 404, `X-Robots-Tag: noindex, nofollow` и `Cache-Control: no-store`.
Адрес в браузере при этом сохраняется, поэтому React покажет NotFound.
Новые директивы полного сайта, включая `Header`, ещё нужно проверить на easyname.

Конфигурация проверена отдельно на Apache 2.4: 143 HTTP-проверки, включая
все 63 маршрута, завершающие слеши, query, отсутствующие файлы, 404 и защиту
`.private`. Использовались тестовая HTML-страница и статический файл вместо
PHP-обработчика; эти проверки подтверждают маршрутизацию Apache, а не исполнение
React, PHP или SMTP. Реальная отправка PHP отдельно проверена на easyname.
Сам Vercel эти `.htaccess` не использует.
Обычный встроенный PHP-сервер `.htaccess` не читает: интеграционные тесты
используют небольшой временный PHP-router, API-правило Apache уже проверено на easyname; полный набор правил пока проверен отдельно.

## Проверки без отправки настоящих писем

Если на компьютере доступны PHP, Composer и Node.js:

```powershell
php tests/easyname/contact.test.php
node --test tests/easyname/contact-http.test.js
```

Первоначальные проверки выполнялись на PHP 8.3.6. Пользователь также успешно
выполнил 36 проверок обработчика и 6 интеграционных проверок на Windows
с PHP 8.5.12. Интеграционные проверки повторены после перехода на `.private`: 6 passed.
На easyname обработчик также проверен на PHP 8.2.35: GET `/api/contact.php`
вернул 405, а тестовый POST — `ok: true`; настоящее письмо получено.

Первый тест проверяет обработку данных и MIME-письмо. Второй запускает локальные
серверы PHP и SMTP/TLS, создаёт одноразовый сертификат и проверяет успешную отправку
и отказ SMTP. Доверие этому сертификату задаётся только тестовому процессу PHP.
Проверка сертификатов в рабочем обработчике не отключается.

Если PHP не находится командой `php`, установка этой среды — отдельный шаг.
Для обычной разработки React по-прежнему достаточно `npm run dev`.
Vite не исполняет PHP, и Vercel Preview не сможет проверить этот обработчик.

## Подготовка пакета без публикации

После установки Composer-зависимостей:

```powershell
node scripts/package-easyname-contact.js
```

Создаётся `hosting/easyname/package/`: публичный обработчик, закрытый код,
PHPMailer, образец конфигурации и инструкция. Пароль намеренно не копируется,
даже если локальный заполненный `contact-config.php` уже существует.
Это пакет только для формы, не полная сборка сайта.
